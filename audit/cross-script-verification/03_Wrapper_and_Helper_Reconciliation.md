## Wrapper reconciliation

Short forwarding functions are classified as candidates rather than asserted wrappers solely by size. For each, Stage 1 records the existing target and target declaration arity. No modular duplicate definitions were found. Missing menu callbacks cannot be classified as valid wrappers because no declaration exists. Return propagation is preserved only where the body explicitly returns the target call; otherwise a void workflow wrapper is treated as intentionally non-returning pending runtime tests.

## Helper reconciliation

* Cross-module consumers are calculated against the full ten-file global namespace, never local-file usage alone.
* A zero-static-caller function is only **potentially orphaned**, not confirmed orphaned: dynamic strings, Apps Script public invocation, QA/test utilities, and external consumers cannot be disproved from these sources.
* Functions missing from modules but present in the combined scripts are classified in Stage 1 as source-population omissions, not orphaned helpers.
* Errors generally propagate unless caught in the recorded body. Best-effort logging catches are not proof that workflow-level errors are swallowed.
