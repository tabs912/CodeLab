# Module 2 v2.18.5 / Module 5 v3.25.1 Release Notes

## Functional summary

Format Raw Data now adds a `#` column to column A of the unformatted source
before any other Raw Data transformation. Row 2 starts at 1 and numbering
continues sequentially through the final used source row. The governed formatted
Raw Data output receives the same `#` column as its first Section H column.

## Change log

- Insert source column A when it is not already the governed `#` column.
- Batch-write the header and complete sequential number series in one call.
- Make repeated execution idempotent by reusing an existing column A `#`.
- Run numbering before title collection, source reads, mapping, pruning, banner
  synchronization, totals, and output formatting.
- Add `#` to Format Dashboard Sections G and H and increase the Raw Data
  structural column count.
- Capture the source-integrity snapshot after intentional row numbering so all
  subsequent processing must still leave Source - Raw Data unchanged.

## Dependency and performance impact

Numbering uses one column insertion when required and one batched value write.
Copying to formatted Raw Data occurs through the existing in-memory Section H
header mapper without additional per-row Spreadsheet calls.

## Test plan

1. Format an unnumbered Raw Data source and verify A1 is `#`, A2 is 1, and the
   final used row has the expected sequential number.
2. Verify formatted Raw Data contains `#` as column A with matching values.
3. Re-run with an existing `#` column and verify no duplicate column is added.
4. Confirm aged-disenrollment pruning affects only formatted Raw Data rows.
5. Confirm the post-numbering source-integrity check still passes.

## Known issues intentionally unchanged

The source tab is still renamed and hidden by lifecycle governance after the
formatted output and source-integrity verification complete.
