# Module 2 v2.12.1 Release Notes

## Summary

Module 2 v2.12.1 fixes the Raw Data formatter failure `normalizeHeader_ is not defined`.

## Root cause

The v2.10-v2.12 Raw Data source-only column helpers referenced `normalizeHeader_()`, which is not part of the modular production set. The shared modular header mapper normalizes headers with trimmed, case-insensitive keys instead.

## Correction

- Added the local `normalizeRawPreservationHeader_()` helper.
- Updated `appendSourceOnlyHeaders_()` and `getSourceOnlyHeaders_()` to use the local helper.
- Matched the normalization behavior used by `buildHeaderIndexMap_()` and `findHeaderIndex_()`.
- Removed every `normalizeHeader_()` runtime dependency from the current Module 2 production script.

## Preserved behavior

- Module 2 v2.12 remains the implementation base.
- Sheet-governance preflight behavior is unchanged.
- CP Due and Unlock CP source-date behavior is unchanged.
- Raw Data source-only column append and post-write verification behavior is unchanged.
- Dashboard Section G number formats remain active.

## Test plan

1. Run Format Raw Data with an RD import containing only governed headers; confirm the route completes.
2. Repeat with mixed-case governed headers; confirm no duplicate source-only columns are appended.
3. Add source-only headers with surrounding spaces and mixed case; confirm they are deduplicated case-insensitively.
4. Confirm Framework Timing reports `Raw Data - Verify source-only columns`.
5. Search the v2.12.1 production script and confirm there are no calls to `normalizeHeader_()`.
