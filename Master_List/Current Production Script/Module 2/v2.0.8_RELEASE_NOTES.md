# Module 3 Full-Width Operational Filter — v2.0.8

## Functional summary

Operational templates now create their filter from the governed header row through the absolute final column and row of the sheet. Extending the filter to the full sheet width removes the visible vertical boundary caused by stopping before the last column.

## Change log

- Changed `applyOperationalTemplateSort_()` to use `sheet.getMaxColumns()` instead of stopping one column before the populated range.
- Anchored the filter at the shared `HEADER_ROW` constant.
- Kept the filter range at a minimum of two rows.
- Removed the unused dashboard globals argument from both operational-template callers.
- Preserved the v2.0.7 dashboard-governed title and six-row subheader formatting changes.

## Dependencies and compatibility

- Deploy with the other four scripts listed in `CURRENT_MODULES_README.md`.
- Module 1 supplies the shared `HEADER_ROW` constant.
- Existing public template-builder entry points are unchanged.

## Performance impact

The filter is still created in one Spreadsheet service call. Its column range now covers the complete sheet width.

## Test plan

1. Build each operational template and verify its filter begins at `HEADER_ROW`.
2. Verify the filter ends at `sheet.getMaxColumns()` and no vertical boundary line appears before the sheet edge.
3. Rebuild a sheet with an existing filter and verify the old filter is removed before the replacement is created.
4. Verify the filter covers at least two rows on a minimal template.
5. Re-run title and six-row subheader formatting checks from v2.0.7.

## Known issues

- Google Sheets controls the native visual styling of the filter and its controls.
