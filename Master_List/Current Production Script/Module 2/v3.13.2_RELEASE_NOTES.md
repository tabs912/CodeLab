# Module 2 Dashboard-Governed Formatting Release Notes — v3.13.2

## Functional summary

All formatting applied by the general template, title-row, and subheader-row pipelines is now read from `Format Dashboard` or `Default - Format Dashboard`. Missing formatting configuration fails with a descriptive error instead of silently substituting code-level fonts, colors, sizes, alignments, wrapping, borders, row heights, or column widths.

## Change log

- Added Module 3 v2.0.2 and Module 5 v3.13.2 without overwriting prior production versions.
- Removed hard-coded formatting fallbacks from the general template pipeline and base-template creation.
- Added strict validation of dashboard globals, theme levels, title-row specifications, and subheader-row specifications.
- Applied existing dashboard section banners and header rows from Section F row-formatting records.
- Applied title rows exclusively from Section E row-formatting records.
- Applied generated subheader blocks exclusively from Section F row-formatting records.
- Loaded fonts, font weights, background colors, alignment, wrapping, border enablement/color/style, number formats, row heights, freeze settings, and column widths from dashboard configuration.
- Reloaded dashboard configuration after writing the data-only default dashboard and before invoking `buildGeneralTemplate_`.
- Removed hard-coded HSL theme and theme-color fallbacks; themes now require dashboard settings and structural rows.

## Dependency impact

- Module 5 v3.13.2 requires Module 3 v2.0.2.
- Existing function names and menu callbacks remain unchanged.
- Dashboard Sections A, C, E, and F must contain complete formatting values. Blank required values now stop the build rather than applying an implicit style.

## Performance impact

- Dashboard content remains a single batch write.
- Baseline formatting and borders are applied to ranges in batches.
- Section banners and headers use the dashboard specifications without cell-by-cell formatting.
- Default row heights use `setRowHeights` as a single batch operation.

## Test plan

1. Build `Default - Format Dashboard` without an active `Format Dashboard` and confirm bootstrap data is written before formatting.
2. Confirm the general formatting pass reads the newly written default dashboard.
3. Change Standard Font, Standard Font Size, Standard Font Color, alignment, wrap, border color/style, row heights, freeze settings, and default column width in the dashboard; rebuild and confirm each change is reflected.
4. Change Section E title-row formatting and confirm all title rows reflect it.
5. Change Section F rows 1–6 and confirm generated subheaders reflect each configuration row.
6. Change Section F rows 2 and 4 and confirm existing dashboard section banners and governed header rows reflect them.
7. Blank each required formatting field in turn and confirm the build stops with a descriptive configuration error.
8. Build all other system and operational templates to confirm they continue through the general template pipeline.

## Known issues intentionally unchanged

- The recovery content matrix remains code-backed so a missing dashboard can be recreated. Once written, formatting is read from the dashboard data rather than from formatter literals.
- Google Apps Script Spreadsheet service behavior must be validated in the bound workbook.
