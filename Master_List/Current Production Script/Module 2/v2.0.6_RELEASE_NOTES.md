# Module 3 Slash-Delimited Column Formatting — v2.0.6

## Functional summary

Column-specific title, subheader, date-label, and width formatting now consistently uses `/` as the column separator. Empty slash positions mean that the corresponding column is not changed.

## Change log

- Retained slash-position mapping for Font Size, Font Weight, Alignment, Wrap, and Title Date Format.
- Changed Section C `Default Column Widths` parsing to use `/` exclusively instead of accepting comma-delimited values.
- Preserved empty width positions as “no change” rather than replacing them with the global default width.
- Preserved scalar values as the existing uniform whole-range behavior when no slash is present.

## Dependencies and compatibility

- Deploy with Module 5 v3.17, which supplies slash-delimited defaults.
- Existing public template-builder entry points are unchanged.
- Comma-delimited custom width lists must be converted to slash-delimited lists.

## Test plan

1. Set a title-row Font Size to `14/ /5` and verify only columns A and C change.
2. Set Default Column Widths to `120/ /240` and verify column B remains unchanged.
3. Build templates from Default - Format Dashboard and Format Dashboard.
4. Run JavaScript syntax validation across all five current modules.

## Known issues

- A literal slash inside a Title Date Format value is interpreted as a column separator.
