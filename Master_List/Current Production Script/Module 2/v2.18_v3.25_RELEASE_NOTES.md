# Module 2 v2.18 / Module 5 v3.25 Release Notes

## Functional summary

Monthly Change and Refined Data updates are now section-aware. The Format
Dashboard schema adds `Bed Bug` between `Safety - 2 Person` and `Wanderer`, and
Archive - Refined Data records the Monthly Change section that caused each
archived update.

## Change log

- Add `Bed Bug` to Section G and to every applicable Section H sheet definition.
- Increase affected Section C column counts and add the complete governed
  Archive - Refined Data header schema, including `Section Changed`.
- Limit Monthly Change output to Primary PMR Row records except Contact Changes,
  which retains all rows for each changed PMR.
- Treat Enrollments and Contact Changes as full-PMR additions with update status
  `Added`; treat other governed section changes as targeted `Updated` records.
- Archive pre-update rows with the triggering section name.
- Run contact compression first only for Added records, followed by remaining
  transforms for Added and Updated records in the prompted month.
- Sort final Refined Data rows A-Z by Last Name.
- Validate Refined Data enrollment and Disenrolled Exclusion totals against the
  prompted Raw Data sheet.
- Write `Last Updated:` timestamps to G2 whenever G1 totals are refreshed.

## Dependency and performance impact

The update reads the existing Monthly Change report once and applies changes in
memory by PMR and section. Archive writes remain batched. Safety validation uses
already-loaded matrices except for the final Disenrolled Exclusion comparison,
which reads the prompted Raw Data sheet once.

3. Exercise each Monthly Change section and verify row selection, target fields,

5. Confirm Refined Data is sorted by Last Name.

## Known issues intentionally unchanged

The existing Monthly Change section titles, tab ranking, visibility, and yellow
changed-cell highlights remain unchanged.
