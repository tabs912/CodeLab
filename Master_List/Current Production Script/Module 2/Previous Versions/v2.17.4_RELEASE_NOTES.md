# Module 2 v2.17.4 Release Notes

## Functional summary

Refined Data and Disenrolled Exclusion now refresh their unique participant
totals in cell G1 whenever their update workflows run.

## Change log

- Write `Total Enrollments: <count>` to Refined Data G1.
- Count unique `Participant PMR#` values whose `Enrollment Status` is exactly
  `Enrolled`, using case-insensitive comparison.
- Refresh the Refined Data total after scratch builds, monthly replacements,
  unchanged monthly syncs, and disenrollment removal.
- Write `Total Disenrollments: <count>` to Disenrolled Exclusion G1.
- Count each nonblank PMR in Disenrolled Exclusion once, including hidden
  historical rows, and refresh the total after every disenrollment update.

## Dependency and performance impact

Both totals use matrices already loaded by their workflows and in-memory `Set`
collections. Each updated sheet receives one G1 write and no additional
full-sheet read solely for counting.

## Test plan

1. Build and update Refined Data with duplicate rows for the same PMR.
2. Verify G1 counts unique PMRs with status `Enrolled` only.
3. Run a monthly sync with no changed PMRs and verify G1 is still refreshed.
4. Update Disenrolled Exclusion and verify G1 counts unique PMRs across all
   current and hidden historical rows.
5. Re-enroll a participant and verify both sheet totals refresh.

## Known issues intentionally unchanged

Raw Data retains its existing three-line participant summary in G1.
