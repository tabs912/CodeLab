# Module 2 v2.14 Release Notes

## Summary

Module 2 v2.14 restores Monthly Change-driven Refined Data replacement and expands the Monthly Change comparison to evaluate every Raw Data row for each PMR.

## Changes

- Monthly Update reads the changed PMR set from the governed Monthly Change report.
- Every changed PMR is rebuilt from all of its current-month Raw Data rows and runs through the complete Refined Data transformation pipeline.
- Existing Refined Data rows are fully replaced rather than updating only address fields.
- Replacement coverage is validated both before and after Refined Data processing; Refined Data is not changed when a PMR lacks a fresh replacement.
- Every removed Refined Data row is appended to `Archive - Refined Data` with Archived At, Archive Reason, Source Workflow, Source Month, and Source Sheet metadata.
- Monthly Change compares multi-row PMR groups as sorted value collections instead of reducing each PMR to one lookup row.
- Disenrollment qualification requires the effective date to equal the prompted report month's first day.
- Demographic comparison includes Participant Name, Name, Preferred Name, and Date of Birth.
- Banner Summary and all six Banner fields have a dedicated change category.
- Changed report cells receive the v1.8.9.3 highlight color `#f3ffc7` through a batched background write.
- Governed Monthly Change reports are still created when all sections are empty; only nonempty blocks receive data rows.

## Approved decision

- No additional Monthly Update preflight is added because the sheet-governance gateway covers creation and replacement policy.

## Test plan

1. Create a Monthly Change report containing demographic, contact, Banner, and disenrollment changes.
2. Confirm all rows for a multi-row PMR are compared and included in applicable sections.
3. Confirm only cells belonging to changed fields use `#f3ffc7`.
4. Run Update Refined Data and verify only Monthly Change PMRs are fully rebuilt.
5. Remove a changed PMR from current Raw Data and verify replacement aborts before Refined Data changes.
6. Verify every removed Refined Data row appears in Archive - Refined Data with all five metadata fields.
7. Run a no-change month and confirm the governed empty Monthly Change sheet is created.
