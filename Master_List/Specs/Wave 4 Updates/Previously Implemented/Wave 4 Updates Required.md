Repeated explanations and alternative code samples are represented once as a requirement; materially different alternatives, constraints, lifecycle rules, and deletion instructions remain separate entries. The `keep` placeholder contains no requirements and is listed in the coverage table for completeness.

**Implementation status legend:** `✅ Complete` means the governing production source contains the requested behavior; `🟡 Partially implemented` means an entry point or part of the behavior exists but one or more specified details, integrations, or cleanup checks remain; `❌ Not implemented` means the requested behavior was not found; and `⚠️ Decision required` means contradictory specifications prevent a completion determination. Statuses are static-audit findings, not runtime certification. Several source files describe proposed code as though it were complete, so function-name presence alone was not treated as proof of completion.
