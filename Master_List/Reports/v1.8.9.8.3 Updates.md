# Master List v1.8.9.8.3 Updates

## Release purpose

Version **v1.8.9.8.3** applies the approved source-level corrections from **Wave 4 v2 Corrections.md** and **v1.8.9.8.2 - Wave 4 Corrections v2.csv** to the v1.8.9.8.2 production baseline. The prior production file remains unchanged.

## Functional changes

- Establishes `RFF_TEMPLATE_BASELINE_ROWS` as the canonical 100-row template baseline, removes `resolveTemplateRowCount_`, and removes the duplicate `enforceTemplateDateAndNumberFormats_` pass.
- Retains `applyGovernedTextAndNumberFormats_` as the governed template text/date/number-format pass and removes redundant data-grid typography/border repainting from `updateBaseTemplateCanvas_`.
- Coerces PMR, phone, ZIP, and postal values to strings during governed header mapping before output writes.
- Adds per-PMR Refined Data contact-flattening isolation with a Primary PMR-row fallback and fixed-width output arrays.
- Preserves `processDemoP` as a public compatibility callback while routing it directly to `buildRefinedDataFromScratch`; removes the obsolete working-source and processing-sheet helpers.
- Adds a native-Date first-seen disenrollment stamp, a missing/empty Refined Data guard, and removal of the Disenrolled Exclusion post-insert format brush.
- Updates Monthly Change sections to the governed five-row block and connects the shared sub-header helper.
- Corrects `replaceSectionDataInTemplate_` to use the Offset 4 insertion anchor.
- Rebuilds Framework Timing and Dashboard Quality payloads as master in-memory buffers with one primary `setValues` body write per report refresh.

## Preserved governance and compatibility

- Existing public menu callback names remain available.
- Master List continues to route through `buildMasterListFromRefinedData` and existing compatibility callbacks.
- Approved monthly workflow order, archive ownership, PMR mapping rules, and output sheet naming remain unchanged.
- v1.8.9.8.2 remains available as the rollback source.

## Dependency and performance impact

- No new external libraries, OAuth scopes, properties, triggers, or deployments are introduced.
- Template construction performs one governed format pass and uses a fixed baseline.
- Dashboard Quality and Framework Timing body payloads are assembled before their principal grid write.
- Runtime formatting required by the five-row visual standard remains after the body write; therefore, the release does not claim zero Google Sheets API calls.

## Required validation

1. Run `buildAllTemplatesAndValidate()` and confirm every configured template passes and retains the 100-row baseline.
2. Run B, CD, UC, and RD monthly formatters with leading-zero PMR, phone, and ZIP values.
3. Test Refined Data with zero, one, eight, and more-than-eight contacts, including malformed data isolated to one PMR.
4. Test Disenrolled Exclusion with missing, empty, active, re-enrolled, and historical participant data; verify native `mm/dd/yyyy` first-seen dates.
5. Run Monthly Change and verify every section follows the five-row structure without overwriting adjacent sections.
6. Run Dashboard Quality and Framework Timing; verify section content, merged title bars, headers, row heights, and report-body write counts.
7. Run Monthly Start and Monthly Update against a privacy-safe workbook copy and compare timing with v1.8.9.8.2.
8. Execute menu/callback, trigger, dynamic-string, archive, Index, and Master List regression checks.

## Known verification requirements

- Google Apps Script runtime and live-workbook visual validation are still required; local JavaScript syntax validation cannot emulate Spreadsheet service behavior.
- The requested Raw Data runtime target of less than three seconds is an acceptance benchmark, not a source-code guarantee.
- Format Dashboard retains its governed configuration-specific layout because replacing that schema with report-style section blocks would change parser row contracts. Its existing section formatting must be visually validated separately.
