# Master List v1.8.9.8.4.1 Updates

## Release purpose

Version **v1.8.9.8.4.1** applies the exact replacement corrections defined in **Wave 4 v4Corrections.md** to the v1.8.9.8.4 production baseline. The prior production release remains unchanged as the rollback source.

## Implemented corrections

- Retains the expanded **Format Dashboard Section E — System Sheet Surfaces** schema, including `Uses Subheaders` and the complete governed header order.
- Replaces `buildSystemSheets()` with the approved Section E-driven physical builder and explicitly skips `RFF_BASE_TEMPLATE`.
- Replaces `setupSystemSheets()` with the approved sequence: build system sheets, rebuild Format Dashboard defaults, ensure Framework Timing, run Dashboard Quality startup, and notify completion.
- Replaces `ensureDashboardQualitySheetShellForWorkflow_()` with direct shell validation, eliminating the removed signature-getter dependency.
- Replaces `assignPrimaryPMRRowsInData_()` with deterministic first-normalized-PMR assignment that does not depend on block-sorting helpers.
- Applies Care Plan metadata formatting to the complete merged `C1:D1` target range at 5pt with WRAP.
- Retains Raw Data Primary PMR processing, Banner synchronization, and explicit unhide-all-columns behavior.
- Replaces `formatMonthlyChangeSubsectionBlock_()` so all written Monthly Change subsection blocks route directly through `applySubHeaderBlock_` using the governed five-row offsets.
- Preserves the required menu bindings for **Build System Sheets**, **Set up System Sheets**, and **System Set up**.

## Compatibility and ownership

- `RFF_BASE_TEMPLATE` remains owned by the template build workflow and is explicitly excluded from `buildSystemSheets()`.
- Existing public workflow names and menu callback names remain unchanged.
- Raw Data continues to use normalized PMR matching, template-copy output generation, approved post-processing, and external source archival.
- No external library, OAuth scope, trigger, property, or deployment change is introduced.

## Required runtime validation

1. Run `buildSystemSheets()` and confirm all configured Section E system sheets except **RFF_BASE_TEMPLATE** are physically available and receive governed column widths.
2. Run `setupSystemSheets()` and verify its exact build → dashboard defaults → timing → quality sequence.
3. Run `quickSystemSetup()`, `runDashboardQualityStartUp()`, `runDashboardQualityValidateTemplates()`, and `runFullQualityCheck()` and confirm no ReferenceError.
4. Format Raw Data containing repeated, blank, whitespace-padded, and `.0`-suffixed PMRs; verify one `Yes` per normalized PMR.
5. Verify Raw Data Banner safety-field synchronization and confirm no Raw Data output columns remain hidden.
6. Format Care Plan Due and Unlocked Care Plan and verify the entire merged `C1:D1` metadata range is 5pt and wrapped.
7. Build Monthly Change and verify each subsection uses the five-row standard without overlap or inherited header formatting in data rows.
8. Confirm the Section E header order and `Uses Subheaders` values after Format Dashboard defaults rebuild.
9. Run Monthly Start and Monthly Update against a privacy-safe workbook and compare output integrity and timing with v1.8.9.8.4.

## Known runtime requirements

Local JavaScript syntax and static source validation cannot emulate Google Sheets range merges, menu execution, sheet visibility, archive access, column hiding, or workbook rendering. Complete live-workbook validation is required before deployment.
