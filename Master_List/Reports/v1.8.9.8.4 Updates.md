# Master List v1.8.9.8.4 Updates

## Release purpose

Version **v1.8.9.8.4** applies the approved **Wave 4 v3 Corrections** to the v1.8.9.8.3 production baseline. The previous production file remains unchanged as the rollback source.

## Functional changes

- Expands **Format Dashboard Section E — System Sheet Surfaces** into a self-contained governance schema for title rows, filters, alternating colors, subheaders, hidden-template policy, output visibility, default column widths, title colors, and notes.
- Adds `buildSystemSheets()` as the dedicated Section E-driven physical system-sheet builder.
- Refactors `setupSystemSheets()` to populate defaults when needed, build governed system surfaces, create specialized Quality/Timing shells, rebuild Index, and enforce tab order.
- Prevents `buildSystemSheets()`, `setupSystemSheets()`, and `initializeSystemSheets_()` from creating `RFF_BASE_TEMPLATE`; golden-master construction remains owned by `buildAllTemplatesAndValidate()` and template workflows.
- Removes the Dashboard Quality dependency on the deleted template-signature getter and validates shell structure directly.
- Restores Raw Data post-processing for Primary PMR assignment and Banner safety-field synchronization.
- Keeps all Raw Data output columns visible by bypassing Section G output hiding for Raw Data.
- Enforces 5pt wrapped metadata in `C1` for Care Plan Due and Unlocked Care Plan outputs.
- Converts Format Dashboard sections to the governed five-row structure and continues shared five-row rendering for Framework Timing, Dashboard Quality, and Monthly Change.
- Keeps **Template - Monthly Change** free of prepainted subsection blocks; runtime output injects those blocks through `applySubHeaderBlock_`.
- Adds Quick Start and Start-up menu bindings for **Build System Sheets**, **Set up System Sheets**, and **System Set up**.

## Configuration migration

An existing pre-v1.8.9.8.4 Format Dashboard does not contain the expanded Section E columns or five-row section offsets. Running `buildSystemSheets()` or `setupSystemSheets()` detects that legacy structure and rebuilds the Format Dashboard from current governed defaults before system sheets are built. Administrators should preserve any intentional local dashboard overrides before first execution and reapply approved values to the expanded schema.

## Preserved governance and compatibility

- Public monthly, template, Dashboard Quality, Framework Timing, Master List, and Index callbacks remain available.
- Raw Data still uses the unified template-copy and external source-archive lifecycle.
- PMR matching uses normalized trimmed strings with whitespace and trailing `.0` removed.
- Existing report templates and `RFF_BASE_TEMPLATE` are not created by system setup.
- No external library, OAuth scope, property, trigger, or deployment change is introduced.

## Required validation

1. Preserve approved Format Dashboard overrides, run `buildSystemSheets()`, and verify the expanded Section E columns and six governed surface rows.
2. Confirm `buildSystemSheets()` creates/updates **Format Dashboard**, **Framework Timing Report**, **Dashboard Quality Report**, **Index**, and **Archive - Demo P**, but does not create **RFF_BASE_TEMPLATE**.
3. Run `setupSystemSheets()` and verify specialized system shells, output visibility, column widths, Index rebuild, and tab ordering.
4. Run `quickSystemSetup()`, `runDashboardQualityStartUp()`, `runDashboardQualityValidateTemplates()`, and `runFullQualityCheck()` and confirm no signature ReferenceError.
5. Format Raw Data and verify exactly one Primary PMR Row per normalized PMR, Banner safety-field parity, and zero hidden output columns.
6. Test PMRs containing leading/trailing spaces and spreadsheet numeric suffix `.0` against the Banners source.
7. Format Care Plan Due and Unlocked Care Plan and verify merged `C1:D1` metadata with `C1` at 5pt and WRAP.
8. Verify five-row offsets, fills, row heights, insertion anchors, and section boundaries on Format Dashboard, Framework Timing, Dashboard Quality, and Monthly Change.
9. Rebuild **Template - Monthly Change** and verify no prepainted subsection blocks exist below the main Row 4 header.
10. Run Monthly Start and Monthly Update against a privacy-safe workbook and compare data integrity and timing with v1.8.9.8.3.

## Known runtime requirements

- Local syntax and static callback checks cannot emulate Google Sheets merges, filters, banding, visibility, menus, archive access, or workbook rendering.
- Live-workbook validation is required before production deployment.
- The Format Dashboard migration intentionally rebuilds legacy dashboard content from current defaults; approved local overrides must be preserved and re-entered.
