# Master List v1.8.9.8.3.1 Updates

## Release purpose

Version **v1.8.9.8.3.1** rebuilds the v1.8.9.8.3 production line with the approved Wave 4 v3, v4, and v5 corrections. The original v1.8.9.8.3 production file remains unchanged as the rollback source.

## Implemented corrections

- Expands **Format Dashboard Section E — System Sheet Surfaces** with the exact governed header order, including `Uses Subheaders`, visibility, width strings, and title-color governance.
- Adds the exact decoupled `buildSystemSheets()` and `setupSystemSheets()` workflows and prevents system setup from creating `RFF_BASE_TEMPLATE`.
- Updates `onOpen()` and `ML_MENU_CALLBACKS` for **Build System Sheets**, **Set up System Sheets**, and **System Set up**.
- Replaces Dashboard Quality shell verification with direct shell validation and removes obsolete signature getter/setter and signature-note infrastructure.
- Replaces Primary PMR assignment with deterministic first-normalized-PMR selection.
- Replaces `formatMonthlySubReportViaTemplate_()` with the approved unified formatter, including full-range 5pt Care Plan metadata, Raw Data Primary PMR processing, Banner synchronization, all-column unhiding, and non-Raw-Data-only column hiding.
- Routes Monthly Change subsection formatting directly through the governed five-row `applySubHeaderBlock_()` implementation.
- Preserves public compatibility wrappers for Refined Data, Disenrolled Exclusion, Monthly Change, and Master List.

## System surface architecture replacement

- Removes the legacy `applySystemSurfaceStructure_()`, `buildSystemSheetsCore_()`, and `initializeSystemSheets_()` implementations and their remaining callers.
- Ports the six-row system-section geometry, 10px visual spacers, safe native banding, Section E theme calculation, and automatic dashboard color recalculation from **System Sheets Test Script.gs**.
- Replaces Dashboard Quality and Framework Timing section replacement with non-destructive section writers and continuous detail-log append behavior.
- Changes system setup order to rebuild dashboard defaults before physical system-sheet creation and forces an Index shell rebuild after timing and quality initialization.
- Preserves `getThemeColorsFromBase_()` byte-for-byte as the independent Section C report theme engine.

## Deduplication and legacy purge

- Confirms every declared function name occurs exactly once.
- Removes the superseded Monthly Change spacer formatter after routing subsection formatting to the shared five-row engine.
- Removes unused generic section replacement, Master List fusion, Dashboard Quality flush, and Framework Timing flush helpers that had no static callers after the master-buffer refactor.
- Removes the unused template-signature key helper and Dashboard Quality signature calculation/storage routines.
- Retains public compatibility aliases even where their one-line bodies are identical because those names are protected callback surfaces.
- Retains active system-shell rebuild functions; they clear content for governed reconstruction but do not call `clearFormat()` or delete row-height definitions.

## Compatibility and ownership

- `RFF_BASE_TEMPLATE` remains exclusively owned by `buildAllTemplatesAndValidate()` and template creation workflows.
- Existing public monthly and data-processing callback names remain unchanged.
- Raw Data continues to use the template-copy, post-processing, Banner synchronization, and external source-archive lifecycle.
- No external library, OAuth scope, trigger, property, or deployment change is introduced.

## Required runtime validation

1. Run `rebuildFormatDashboardDefaults()` and confirm the exact Section E header order and six default system-surface rows.
2. Run `buildSystemSheets()` and confirm every configured system sheet except **RFF_BASE_TEMPLATE** is created and receives governed widths.
3. Run `setupSystemSheets()` and confirm its build → dashboard defaults → timing → Dashboard Quality sequence.
4. Run `quickSystemSetup()`, `runDashboardQualityStartUp()`, `runDashboardQualityValidateTemplates()`, and `runFullQualityCheck()` and confirm no ReferenceError.
5. Format Raw Data with repeated, blank, whitespace-padded, and `.0`-suffixed PMRs; verify one Primary PMR `Yes` per normalized PMR.
6. Confirm Raw Data Banner safety fields synchronize and no Raw Data columns remain hidden.
7. Format Care Plan Due and Unlocked Care Plan and verify merged `C1:D1` metadata is 5pt and wrapped.
8. Build Monthly Change and verify every subsection follows the five-row standard without overlap or header-format inheritance in data rows.
9. Execute every public menu callback and the System Sheets Test Script against a privacy-safe workbook.
10. Run Monthly Start and Monthly Update and compare output integrity and timing with v1.8.9.8.3.

## Known runtime requirements

Local JavaScript syntax and static source checks cannot emulate Google Sheets merges, sheet visibility, archive access, menu execution, or workbook rendering. Complete live-workbook validation is required before deployment.
