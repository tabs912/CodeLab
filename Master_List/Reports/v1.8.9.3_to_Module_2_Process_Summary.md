## Workflow process summary

### Format Monthly Sheets

1. Routes Banners, CP Due, Unlock CP, and Raw Data independently.
2. Uses governed sheet creation, collision handling, rank, visibility, and F1 governance metadata.
3. Archives Banners, CP Due, and Unlock CP sources before deleting their local imports.
4. Creates governed Raw Data, preserves undeclared imported columns, verifies the preserved values after write, and retains the original import as a hidden source tab.
5. Synchronizes Banner fields and Banner Summary into Raw Data.
6. Uses valid CP Due `C3`/`E3` and Unlock CP `E2`/`G2` dates with prompted-month fallback.
7. Runs a fatal all-route import preflight before any source archive, output creation, source rename, hide, or deletion. Processing errors after a successful import preflight remain isolated by route.

### Create Monthly Start

1. Builds Refined Data from all governed Raw Data rows.
2. Applies participant-name, phone, address, language, Banner Summary, contact compression, Notes, and tracking-field processing.
3. Adds new disenrollments to the persistent Disenrolled Exclusion history.
4. Creates Master List from Refined Data with CP Due and Unlock CP enrichment.
5. Uses standard sheet governance rather than staged Master List promotion.

### Create Monthly Update

1. Builds the governed Monthly Change report from current and previous Raw Data.
2. Compares every row grouped by PMR and classifies enrollment, disenrollment, demographic, caseload, contact, Banner Summary, other, and level-of-care changes.
3. Preserves changed-field sets and highlights changed cells.
4. Reads the changed PMR set from Monthly Change.
5. Validates that every changed PMR has current Raw Data, runs all of its rows through Refined Data processing, validates post-processing coverage, archives removed rows with metadata, and replaces complete PMR records.
6. Merges new disenrollments into retained history, performs targeted re-enrollment removal, and asserts copy/removal equality.
7. Rebuilds Master List and refreshes the Index.
8. Creates an empty governed Monthly Change report when no qualifying changes exist, per the approved modular behavior.

## Parity conclusion

Module 2 now implements the material Monthly Change, Refined Data replacement, Disenrolled Exclusion retention, source-date, Banner comparison, highlighting, archive-metadata, and deployable-directory corrections in the remediation list.

All 19 remediation items are now either implemented or covered by an explicit approved modular design decision. The approved Raw Data preserved-source lifecycle and always-created empty Monthly Change sheet remain intentional differences from v1.8.9.3, so reports should describe them as approved differences rather than identical behavior. Runtime workbook tests are still required before production promotion.
