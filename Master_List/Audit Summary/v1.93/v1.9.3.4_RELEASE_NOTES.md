# Master List v1.9.3.4 Subheader Data-Write Restoration Release Notes

## Release

- **Version:** v1.9.3.4
- **Production source:** `Master_List/Current Production Script/v1.9.3.4`
- **Behavioral reference:** `Master_List/Current Production Script/v1.93` (v1.9.3 behavior)
- **Immediate predecessor:** `Master_List/Current Production Script/v1.9.3.3`
- **Rollback source:** `Master_List/Current Production Script/v1.9.3.3`

## Functional summary

v1.9.3.4 restores the v1.9.3 subheader data-write algorithm for Framework Timing, Dashboard Quality, and Monthly Change sections. It removes the v1.9.3.1-derived anchor-search behavior from the shared append path while preserving the v1.9.3.3 timing sections, detailed timing collection, report repair, menu callbacks, business workflows, and template formatting.

## Change log

1. Restored `appendDataToSubheaderSection_` from the v1.9.3 reference implementation.
2. Restored v1.9.3 fixed-offset section data placement (`section title row + 5`).
3. Restored the v1.9.3 next-section boundary calculation and row-insertion behavior.
4. Restored recognition and clearing of the v1.9.3 `Insert new data here` and legacy `Enter Data here` markers at the calculated data row.
5. Preserved existing section formatting by limiting the correction to content placement and row insertion; no template, title, subheader, banding, color, width, height, or border formatting code was changed.
6. Preserved Framework Timing Sections A-D and the v1.9.3.3 ordered detailed-step and summary engines.
7. Preserved Dashboard Quality red failure highlighting after the shared writer returns the appended range.

## Dependency and compatibility impact

- No new libraries, services, scopes, properties, or external resources.
- Existing menu callbacks and public workflow entry points are unchanged.
- Timing, Dashboard Quality, and Monthly Change continue to use the same shared writer.
- Existing templates do not require rebuilding solely for this correction.

## Performance impact

The restored algorithm performs one data-range scan, one bounded search for the target and following section, an optional row insertion, and one batch `setValues` call. No additional formatting or whole-sheet service calls were introduced.

## Test plan

1. Build or open a formatted Framework Timing Report, Dashboard Quality Report, and Monthly Change sheet.
2. Write one result set to every governed section and verify the v1.9.3 row placement.
3. Write a second result set and verify it appends without overwriting the next section title.
4. Confirm existing section fills, borders, fonts, row heights, subheader rows, native banding, and buffer columns remain unchanged.
5. Confirm Dashboard Quality failure cells retain red highlighting.
6. Confirm Framework Timing Sections A-D and detailed step summaries remain populated.

## Known runtime-dependent items

Visual formatting equivalence must be confirmed in the bound spreadsheet because Google Sheets row-insertion format inheritance cannot be completely validated through source-static testing.
