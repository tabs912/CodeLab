# Master List v1.9.3.3 Timing Detail Restoration Release Notes

## Release

- **Version:** v1.9.3.3
- **Production source:** `Master_List/Current Production Script/v1.9.3.3`
- **Timing reference:** `Master_List/Current Production Script/v1.8_Prior`
- **Rollback source:** `Master_List/Current Production Script/v1.9.3.2`

## Functional summary

This correction restores the four governed Framework Timing Report sections, makes every framework timing marker contribute an ordered detailed step, rebuilds missing Timing sections from the governed template, derives summary/issue/recommendation sections from the detailed log, and guarantees that writes to subheader-based sheets begin at the row containing `Insert new data here`.

## Change log

1. Removed duplicate `markFrameworkStep_` and `logBestEffortWarning_` declarations that previously overrode the runtime timing implementation and prevented workflow markers from entering the detailed timing collection.
2. Added an explicit sequence number to every runtime timing step and included the sequence in Section D details.
3. Restored Framework Timing Report sections:
   - Section A — Process Summary
   - Section B — Performance Issues
   - Section C — Optimization Recommendations
   - Section D — Detailed Timing Log
4. Added automatic Framework Timing Report repair. If the active report or its template lacks any required section, the governed Timing template is rebuilt and a complete active report is recreated.
5. Changed Timing writes from bottom-of-sheet appends to governed Section D subheader appends.
6. Added summary regeneration after every timed workflow. Section A aggregates each run and counts its detailed steps; Section B extracts slow, bottleneck, and critical steps; Section C produces corresponding open recommendations.
7. Reworked the shared subheader appender to locate the literal `Insert new data here` or legacy `Enter Data here` anchor instead of relying on a fixed row offset.
8. Ensured subsequent writes append after existing section results and insert rows before the next section rather than overwriting its title or header.
9. Updated Timing/Quality log clearing to preserve all template titles, subheaders, formatting, and section structures while restoring the data-anchor rows.

## Dependency and compatibility impact

- No new external libraries or OAuth scopes are required.
- Uses the existing V8, Spreadsheet, Properties, Utilities, and Logger services.
- Existing public timing functions and menu callbacks remain compatible.
- An existing malformed Framework Timing Report is intentionally replaced from the governed template the next time timing is written or logs are cleared.

## Performance impact

- Each completed timed workflow performs one batched Section D write and three bounded summary-section writes.
- Detailed timing retention remains capped by `RFF_TIMING_MAX_ROWS`.
- Summary generation reads only the governed Section D data region and retains the most recent 100 process runs and 200 performance issues.

## Test plan

1. Delete one Framework Timing section and run a timed workflow; confirm Sections A-D are restored.
2. Run a workflow containing multiple `markFrameworkStep_` calls; confirm every marker appears in Section D in sequence with step and cumulative duration.
3. Confirm the first Section D result replaces the `Insert new data here` anchor row.
4. Run the workflow again; confirm new detail rows append after existing rows without overwriting another section.
5. Confirm Sections A-C refresh from Section D after each run.
6. Force steps over the 10-, 30-, and 60-second thresholds and confirm SLOW, BOTTLENECK, and CRITICAL issue/recommendation rows.
7. Write Dashboard Quality and Monthly Change results and confirm their first data rows also use their `Insert new data here` anchors.
8. Clear Timing and Quality logs; confirm section titles, subheaders, formatting, and anchor rows remain intact.

## Runtime-dependent known items

Live duration thresholds, concurrent trigger execution, and workbook-specific template state require verification in the bound Apps Script spreadsheet.
