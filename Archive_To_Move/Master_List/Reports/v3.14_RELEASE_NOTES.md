# Module 2 Single-Source Dashboard Defaults — v3.14

## Functional summary

The complete Format Dashboard factory dataset is declared once in Module 5. A single section registry now supplies dashboard construction, fallback parsing, section ordering, and dashboard subheader metadata.

Section A adds `Base Template` immediately after `Value`. Each row uses `TRUE` or `FALSE` to determine whether that setting participates in `RFF_BASE_TEMPLATE` formatting.

## Change log

- Added `Current_Modules/` containing one current deployable version of each Module 2 script.
- Removed the duplicate `GLOBAL_DEFAULTS` declaration from current Module 1.
- Added the single `FORMAT_DASHBOARD_SECTION_REGISTRY` over the one `MASTER_FORMAT_DEFAULTS` dataset.
- Replaced eight manual dashboard-section build calls with one registry iteration.
- Replaced eight manual dashboard subheader entries with one registry mapping.
- Parses all fallback section matrices once through the registry.
- Added `Base Template` to Section A after `Value`.
- Added `baseTemplateGlobals` to fallback, live, and template configuration objects.
- Updated base-template construction to use only Section A rows marked `TRUE`.
- Preserved compatibility with an older active dashboard that does not yet contain the new column by retaining recovery markers until that dashboard is rebuilt.
- Updated header/data row placement and row heights from the enabled Section A values.

## Dependency impact

- Current Module 3 v2.0.3 requires current Module 5 v3.14.
- Deploy the five files listed in `Current_Modules/README.md` as one set.
- Do not deploy retained older Module 2 snapshots alongside the current set.

## Performance impact

- Default matrices are parsed once per fallback-config build.
- Dashboard sections and subheader metadata are generated by registry iteration.
- Base-template data-row heights use one `setRowHeights` batch call.

## Test plan

1. Deploy only the five current module scripts.
2. Delete `Default - Format Dashboard` and `Format Dashboard`, then run dashboard setup.
3. Confirm Section A columns are `Setting`, `Value`, `Base Template`, and `Options / Format Description`.
4. Confirm every Section A marker is `TRUE` or `FALSE`.
5. Confirm Sections A–H appear once and in registry order.
6. Confirm `RFF_BASE_TEMPLATE` uses settings marked `TRUE`.
7. Change a `TRUE` marker to `FALSE`, rebuild the base template, and confirm that setting is excluded or a required-setting validation error identifies it.
8. Confirm all system and operational templates still build from dashboard configuration.
