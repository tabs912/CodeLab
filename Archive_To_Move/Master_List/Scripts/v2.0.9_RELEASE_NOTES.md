# Module 3 Section G Date Formats — v2.0.9

## Functional summary

Operational template builds now format every Section G column marked `Date Column = TRUE` with that same Section G row's `Number Format` after the governed headers are written.

## Change log

- Read the `Date Column` and `Number Format` values from each matched Section G column definition during operational template formatting.
- Applied the configured number format to the complete template data-column range after header creation.
- Removed the fallback to the global Default Date Format for Section G date columns.
- Added fail-fast validation when a Section G date column has no Number Format.
- Preserved explicit number formats for non-date columns.

## Dependencies and compatibility

- Deploy with Module 5 v3.19 and the other scripts listed in `CURRENT_MODULES_README.md`.
- Existing operational template builder entry points are unchanged.
- Every Section G row marked as a date column must provide a nonblank Number Format.

## Performance impact

Formatting remains column-batched with one `setNumberFormat()` call per governed column. No per-cell or per-row formatting was introduced.

## Test plan

1. Mark a Section G column as a date column and assign a distinctive Number Format.
2. Build the operational template containing that header.
3. Verify the data range below the header uses the exact Section G Number Format.
4. Verify a missing Number Format on a date column stops the build with a descriptive validation error.
5. Verify non-date columns with explicit Number Format values continue to receive them.

## Known issues

- Date-column definitions not used by a particular template are intentionally ignored.
