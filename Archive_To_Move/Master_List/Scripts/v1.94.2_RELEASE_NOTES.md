# Module 1 Header-Mapped Diagnostic Results — v1.94.2

## Functional summary

Framework Timing output is now written and read by normalized section column-header names. Reordering Timing Report columns no longer changes which result is stored or summarized.

## Change log

- Added shared section-header discovery, normalization, row mapping, and record-reading helpers.
- Changed detailed timing writes to supply seven separately named fields instead of a physical-position array.
- Changed timing summary reads to records keyed by the displayed headers.
- Changed summary, issue, and recommendation writes to map source fields into the current section headers.
- Preserved positional behavior for existing callers that do not supply source headers.

## Dependencies and compatibility

- Deploy with Module 4 v2.1.2 for header-mapped Quality Dashboard results.
- Public timing and workflow entry points are unchanged.
- Existing report templates remain compatible; their columns may be rearranged without changing result placement.

## Test plan

1. Rearrange every Framework Timing section's columns.
2. Run a timed workflow.
3. Confirm detail, summary, issue, and recommendation values appear under their matching headers.
4. Run JavaScript syntax validation across all five current modules.

## Known issues

- Section titles and displayed header names must remain present; arbitrary renaming is not supported beyond the documented normalized aliases.
