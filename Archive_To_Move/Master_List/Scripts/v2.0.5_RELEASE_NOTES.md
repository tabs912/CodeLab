# Module 3 Dashboard-Only Template Formatting — v2.0.5

## Functional summary

All non-base template formatting now comes from `Format Dashboard` or `Default - Format Dashboard`. General, operational, timing, quality, index, archive, and report template builders no longer introduce coded visual defaults or index-specific formatting.

## Change log

- Added Module 3 v2.0.5 and preserved v2.0.4 as a prior release snapshot.
- Updated the column-width engine to accept both comma-delimited and slash-delimited Section C width lists.
- Removed coded operational fallbacks for date format, wrap, horizontal alignment, and vertical alignment.
- Reads Header Row and Data Start Row from Section A instead of fixed row constants during operational formatting.
- Reuses the same parsed dashboard configuration for general and operational formatting passes.
- Requires Index headers from Section H instead of inserting a coded header list.
- Removed coded Index font size, font weight, fills, and conditional formatting.
- Prevents the existing-dashboard path from generating subheader content over populated dashboard sections.
- Uses dashboard Header Row for operational filter placement.

## Dependency impact

- Module 3 v2.0.5 requires the current Module 5 dashboard/configuration module.
- `buildGeneralTemplate_()` and public template-builder names remain compatible.
- Section A must provide Header Row, Data Start Row, default formats, wrap, and alignments.
- Section C must provide per-template column widths.
- Section G must provide column-specific formatting where overrides are required.
- Section H must provide every template's headers, including Index.

## Performance impact

Dashboard configuration is parsed once per operational template build and reused by both formatting passes. No additional spreadsheet reads were introduced.

## Test plan

2. Change Section A date format, wrap, horizontal alignment, vertical alignment, Header Row, and Data Start Row; rebuild and verify all templates.
3. Change Section E title-row formatting and verify Timing, Quality, Index, and operational templates.
4. Change Section F subheader formatting and verify subheader-based templates.
5. Change Section G column overrides and verify widths, header sizes, formats, wraps, and alignments.
6. Change Section H headers and verify every rebuilt template reflects them.
7. Confirm Index has no coded font, fill, or conditional-format overrides.
